# Подготовка колонки

Kas Control подключается к уже настроенной Станции. Контрольная конфигурация — Станция Лайт 2 (Plum), нативный голосовой клиент Linux ARM64 и Windows x64. Совместимость с другими моделями, прошивками и чистыми установками голосового клиента требует отдельной проверки.

## 1. Подготовьте доступ к своей Станции

Для установки голосового клиента и маршрутизатора нужен рабочий административный доступ по SSH. На нашей Лайт 2 использовали описанный в Yandex Station Extended подход с заводским сертификатом из `factory`. Это отдельная ветка подготовки для Plum. Модель, поддерживаемые конфигурации и восстановление доступа сверяйте с документацией сообщества Marker284. [Yandex Station Extended / HackAlice](https://hackalice.me/) · [Репозиторий проекта](https://github.com/Marker284/yandex-station-extended).

Перед работой с устройством сохраните исходную конфигурацию и способ восстановления. После подготовки убедитесь, что вы можете самостоятельно войти в свою Станцию по SSH. Храните ключи и резервные копии у себя.

## 2. Запустите нативный голосовой клиент

Для голосовых разговоров с выключенным ПК выбран нативный режим Alisa Voice. Сначала настройте обычный голосовой ответ и завершение сеанса. Затем проверьте совместимость интерфейсов установленной сборки. [Alisa Voice](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant).

Контракт для Kas Control 4.0

- Базовый каталог `/data/opt/alisa-standalone`, приложение `bin/alisa-standalone`, `run.sh` и рабочие настройки `state/`.
- Локальный интерфейс управления голосом `127.0.0.1:18080` и поток событий распознавания `127.0.0.1:9875`.
- Для команд проектов с быстрым запасом требуется возможность `prepare_chats_v1` в ответе локального статуса нативного клиента. [Контракт и патч нативного клиента](../native/README.md).

Если установленный клиент не сообщает `prepare_chats_v1`, проверьте применимость патча к его исходникам до замены рабочей сборки. Контекст патча отличается от Alisa Voice 0.3.10. Для установки расширения требуется совместимая база, отдельная сборка клиента и одно обновление с сохраненным откатом. Windows-комплект содержит пульт и архиватор. Маршрутизатор и изменения нативного клиента поставляются отдельно.

## 3. Установите маршрутизатор

Скачайте `Kas-Control-Router-4.0-linux-arm64.zip` из Releases. В нем находятся ARM64-маршрутизатор, сценарии установки и отката. Для команд проектов включите `project_sessions` в `routes.json`. Для уже установленного маршрутизатора сначала сохраните его конфигурацию и текущий бинарник. [Установка, включение режима и откат](../router/README.md).

## 4. Подготовьте Windows

Установите OpenSSH Client и WebView2 Runtime, если они отсутствуют. Создайте SSH-профиль `station`, затем войдите в ChatGPT через пульт под тем же аккаунтом, что используется на колонке. [Настройка профиля и первый разговор](GETTING_STARTED.md).

Готовый комплект работает в Windows без Python и WSL. Установка нативного клиента, обновление маршрутизатора и подготовка Станции выполняются отдельно от запуска пульта.

## Внешние проекты

- **Yandex Station Extended** — справочник по моделям, доступу к своему устройству и восстановлению. [HackAlice](https://hackalice.me/).
- **eQuasar** — самостоятельный проект, упоминаемый в материалах сообщества Станций. [Репозиторий eQuasar](https://git.gay/iwakura/eQuasar).
- **Alisa Voice** — голосовая интеграция, для которой предназначен нативный контракт Kas Control. [Репозиторий Alisa Voice](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant).
- **Pulsar** — материал по работе с дисплеем и сегментной мимикой. [Репозиторий Pulsar](https://github.com/Morvex885/pulsar).
- **login-with-chatgpt** — справочный проект по входу и Live/WebRTC. [Репозиторий login-with-chatgpt](https://github.com/opencoredev/login-with-chatgpt).
