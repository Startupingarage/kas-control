# Подготовка колонки и внешние проекты

Kas Control управляет уже работающим голосовым клиентом на колонке.
Пульт не получает root, не устанавливает прошивку, не настраивает DNS
и не устанавливает ChatGPT Voice автоматически.

Контрольная конфигурация этого проекта — Яндекс Станция Лайт 2 (Plum),
нативный Linux ARM64-клиент на колонке и Windows-пульт с доступом через WSL/SSH.
Совместимость пульта с другими моделями и прошивками отдельно не подтверждена.
Поддержка модели в стороннем проекте не означает, что на ней проверен Kas Control.

## 1. Получить root по инструкции для своей модели

Основной внешний справочник — **Yandex Station Extended / HackAlice**:

- [Сайт и выбор модели](https://hackalice.me/).
- [Исходный репозиторий Marker284/yandex-station-extended](https://github.com/Marker284/yandex-station-extended).
- [Лайт 2 (Plum): root через сертификат из factory](https://hackalice.me/start/retail-ca/).
- [DNS-метод для других подходящих моделей](https://hackalice.me/start/root/).

У Лайт 2 есть отдельная инструкция; не следует считать общий DNS-метод
универсальным для неё и любой версии прошивки. Проверяйте актуальные ограничения
в руководстве для конкретной модели.

Используемый в этих инструкциях проект
[iwakura/eQuasar](https://git.gay/iwakura/eQuasar) предоставляет конфигурацию
подменного сервера Quasar. Это инструмент этапа получения доступа, а не
голосовой движок и не компонент Windows-пульта.
Если прямой сайт репозитория недоступен, ссылка и описание его роли также есть
в [инструкции HackAlice для Лайт 2](https://hackalice.me/start/retail-ca/).

Подготовка затрагивает системные файлы и иногда настройки сети. До её начала
сохраните исходные настройки, изучите откат и не переносите номера разделов
с другой модели. Если root уже работает, повторять процедуру ради пульта не нужно.

## 2. Настроить SSH и восстановление доступа

Продолжение руководства:

- [SSH и обновления](https://hackalice.me/start/ssh/).
- [Диагностика и восстановление](https://hackalice.me/start/recovery/).

До перехода к голосовому клиенту должен работать самостоятельный вход по SSH
с административными правами. Сертификаты, приватные ключи, пароли и резервные
копии остаются у владельца устройства; они не входят в этот репозиторий.

## 3. Установить и проверить ChatGPT Voice отдельно от пульта

Исходный внешний проект голосовой интеграции —
[rison1337/Alisa-ChatGPT-voice-assistant (Alisa Voice)](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant).
Установка и список поддерживаемых моделей находятся в его README и документации.
Сам проект также требует заранее работающие root и SSH.

У Alisa Voice есть нативный режим и режим с браузерным мостом. Для рассматриваемой
конфигурации Kas Control используется нативный клиент на колонке: ПК с пультом
не должен быть постоянно включён. Не следует переносить это свойство на
браузерный мост, которому нужен работающий хост.

Сначала настройте вход в аккаунт ChatGPT, добейтесь голосового ответа и проверьте
обычное закрытие и повторное открытие разговора. После этого подключайте пульт.
Рабочую голосовую установку не нужно переустанавливать ради интерфейса управления.

### Контракт совместимости текущей версии

Ссылка на Alisa Voice не означает, что любая его версия автоматически совместима
с пультом. Текущая интеграция использует следующий локальный контракт:

- `/data/opt/alisa-standalone/bin/alisa-standalone`: команды `status`, `open`, `close`.
- `/data/opt/alisa-standalone/run.sh`: управление существующим голосовым процессом.
- В том же каталоге: `runtime.env`, `state/settings.json`,
  `state/web-session.json` и `state/ui-auth.json`.
- Локальный HTTP-интерфейс управления на `127.0.0.1:18080`
  с авторизацией `X-Standalone-Key` из локального `ui-auth.json`.
- Локальный поток событий распознавания на `127.0.0.1:9875`.

Это требования к существующей установке, а не инструкция создавать пустые
файлы с такими именами. Форматы и вызовы проверяются по
[backend.py](../backend.py), [browser_login.py](../browser_login.py)
и [router/main.go](../router/main.go). Ключи и содержимое файлов аккаунта
не следует публиковать или вставлять в отчёты. Локальные порты не требуется
открывать в интернет.

Совместимость с чистой установкой последней версии внешнего проекта с нуля
в рамках этого репозитория не проверялась. Перед заменой работающей версии
нужно сопоставить её интерфейсы с этим контрактом и сохранить откат.

## 4. Подготовить Windows и обработчик команд

На ПК нужны:

- [WSL](https://learn.microsoft.com/en-us/windows/wsl/install).
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
- Для персональной сборки — дистрибутив `StationLab`, пользователь `stationuser`
  и SSH-профиль `/home/stationuser/kas-live/ssh_config` с узлом `station`.
  Профиль должен обеспечивать вход без интерактивного запроса пароля,
  ключа или подтверждения отпечатка. Эти имена заданы в [backend.py](../backend.py).
- Доступ из сети ПК к колонке и из веб-окна пульта к ChatGPT.

После установки WSL он не получает эти настройки автоматически: необходимо
настроить собственный SSH-профиль. Приватные ключи не включаются в сборку.
Готовый EXE не требует Python; для сборки из исходников он нужен.

На колонке отдельно устанавливается наш
[обработчик голосовых фраз](../router/README.md). Для управления подготовленными
чатами пульт ожидает в его состоянии возможности `catalog` и `lazy_registration`.
Поддержка root сама по себе этих возможностей не добавляет.

До первого назначения команд проверьте, что обработчик запущен, подключён
к локальному потоку и принял конфигурацию. Его установка, ограничения,
автозапуск и откат описаны в `router/README.md`; пульт не запускает установку
обработчика автоматически.

## Дополнительные проекты и благодарности

- [Morvex885/pulsar](https://github.com/Morvex885/pulsar) — отдельный проект
  локального голосового спутника Home Assistant и управления устройством,
  использованный как источник исследований дисплея и сегментных выражений
  в Station Lab. Для Kas Control он не обязателен; код мимики и маски в эту
  поставку пульта не включены. Полный стек Pulsar не следует устанавливать
  поверх рабочего ChatGPT Voice только ради запуска пульта.
- [opencoredev/login-with-chatgpt](https://github.com/opencoredev/login-with-chatgpt) —
  справочный проект по входу через аккаунт ChatGPT и экспериментальному
  Live/WebRTC. Его SDK не является зависимостью Kas Control;
  веб-вход пульта реализован в `browser_login.py`.

Работы этих авторов самостоятельны. Указание ссылки не означает их одобрения
Kas Control, не передаёт права на их код и не заменяет соблюдения их лицензий.
Закрытые условия нашего проекта не распространяются на сторонние компоненты.

Ссылки и описание интерфейсов сверены 1 ноября 2026 года. Внешние инструкции
могут измениться; перед подготовкой другого устройства следует открыть их
актуальные версии и проверить модель и прошивку.
